# Tasks App - Flutter Clean Architecture

Приложение для управления задачами с использованием Clean Architecture, Feature-first организации и flutter_bloc для управления состоянием.

## Возможности

- ✅ **Две связанные таблицы**: Tasks и Tags с foreign key связью
- ✅ **CRUD операции**: Создание, чтение, обновление и удаление задач и тегов
- ✅ **Сортировка**: По дате и приоритету (возрастание/убывание)
- ✅ **Потоковое обновление UI**: Режим watch() для автоматического обновления и get() для ручного обновления
- ✅ **Миграция БД**: Добавлено поле `notes` с значением по умолчанию
- ✅ **Экспорт/Импорт**: Сохранение и загрузка данных в JSON формате

## Архитектура

Проект следует принципам Clean Architecture с Feature-first организацией:

```
lib/
├── core/                          # Общий код
│   ├── error/                     # Обработка ошибок
│   ├── injection/                 # Dependency Injection (GetIt)
│   └── utils/                     # Утилиты
├── features/                      # Функциональность приложения
│   └── tasks/                     # Фича задач
│       ├── data/                  # Слой данных
│       │   ├── models/            # Модели БД (Drift)
│       │   └── repositories/      # Реализации репозиториев
│       ├── domain/                # Слой домена
│       │   ├── entities/          # Бизнес-объекты
│       │   ├── repositories/      # Интерфейсы репозиториев
│       │   └── usecases/          # Use cases
│       └── presentation/          # Слой представления
│           ├── bloc/              # State management
│           ├── pages/             # Экраны
│           └── widgets/           # Виджеты
└── main.dart                      # Точка входа
```

## Технологии

- **Drift** - ORM для работы с SQLite
- **flutter_bloc** - Управление состоянием
- **GetIt** - Dependency Injection
- **Dartz** - Функциональное программирование для обработки ошибок
- **Equatable** - Сравнение объектов

## Установка и запуск

1. Установите зависимости:
```bash
flutter pub get
```

2. Сгенерируйте код для Drift:
```bash
flutter pub run build_runner build --delete-conflicting-outputs
```

3. Запустите приложение:
```bash
flutter run
```

## Использование

### Режимы обновления данных

Приложение поддерживает два режима обновления данных:

1. **watch()** - Автоматическое обновление UI при изменении данных в БД
   - Включено по умолчанию
   - Индикатор "Live updates enabled" вверху списка
   - Изменения отображаются автоматически без необходимости обновления

2. **get()** - Ручное обновление данных
   - Переключите режим кнопкой в AppBar
   - Индикатор "Manual refresh" вверху списка
   - Используйте pull-to-refresh для обновления данных

### Создание задачи

1. Нажмите кнопку "+" в правом нижнем углу
2. Заполните форму:
   - Название (обязательно)
   - Описание (опционально)
   - Приоритет (Low/Medium/High)
   - Тег (опционально)
3. Нажмите "Save"

### Управление тегами

1. Нажмите иконку тега в AppBar
2. Создайте новый тег кнопкой "+"
3. Выберите цвет и название
4. Редактируйте или удаляйте существующие теги

### Сортировка

1. Нажмите иконку сортировки в AppBar
2. Выберите тип сортировки:
   - По дате
   - По приоритету
   - Без сортировки
3. Выберите направление (возрастание/убывание)

### Экспорт/Импорт

1. Нажмите иконку импорта/экспорта в AppBar
2. **Экспорт**: Нажмите "Export to JSON" - файл будет сохранен в Documents
3. **Импорт**: Нажмите "Import from JSON" и выберите файл

## Структура базы данных

### Таблица Tasks
- `id` - Primary Key, Auto Increment
- `title` - Название задачи
- `description` - Описание
- `createdAt` - Дата создания
- `updatedAt` - Дата обновления
- `priority` - Приоритет (1=Low, 2=Medium, 3=High)
- `isCompleted` - Статус выполнения
- `tagId` - Foreign Key к таблице Tags
- `notes` - Заметки (добавлено в миграции)

### Таблица Tags
- `id` - Primary Key, Auto Increment
- `name` - Название тега
- `color` - Цвет в hex формате

### Связь
- Tasks.tagId → Tags.id (Foreign Key с SET NULL при удалении)

## Миграция

Приложение включает пример миграции (версия 1 → 2):
- Добавлено поле `notes` в таблицу Tasks
- Существующим записям устанавливается значение по умолчанию (пустая строка)

## Особенности реализации

### Watch() vs Get()

**Watch()** - Использует Stream из Drift:
- Автоматически обновляется при изменении данных
- Более эффективен для реального времени
- Использует `emit.forEach()` в bloc

**Get()** - Использует Future из Drift:
- Требует явного обновления
- Подходит для разовых запросов
- Использует обычный async/await в bloc

### Обработка ошибок

Используется функциональный подход с Either<Failure, Success>:
- Left - ошибка (Failure)
- Right - успех (данные)
- Централизованная обработка ошибок через Failure классы
